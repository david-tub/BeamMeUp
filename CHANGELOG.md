## 2026.10.10
- Internal: removed all `pcall` protective wrappers from `TeleporterChecker.lua` (LibSets probes, own-houses cache builder, House Tours collectible/manager probes, House Tours filter methods, per-listing enrichment). Errors now surface to ESO's error handler and, in the LibAsync background builds, to LibAsync's own error handling (OnError/Finally still abort the batch and restore the game's House Tours filters). Behavior is unchanged when no error occurs. Known regression: the synchronous (no LibAsync) fallback is no longer protected, so an error during the House Tours enrichment leaves the search locked until reload.

## 2026.10.08
- LibAsync is now a pure optional external dependency: the embedded copy (`lib/LibAsync/`) was removed and `LibAsync` stays in `OptionalDependsOn` (a standalone LibAsync is loaded before BeamMeUp when installed). At startup BeamMeUp verifies its presence and prints a localized chat hint if it is missing — everything still works via the synchronous fallbacks, but the background caches build in one frame. Install the standalone LibAsync addon to keep the background builds spread over several frames.
- Tooltip on the house name: hovering the displayed house/owner name now shows the house tooltip (house name and nickname for own houses, plus the owner for House Tours; rich content in the Houses tab with icon, category and furniture count). It was previously only shown on the zone-name column. The tooltip follows the list on scroll and pauses auto-refresh while hovered.
- Timing checkpoints for the LibAsync cache builds: each background build (own houses cache, House Tours enrichment) now measures its accumulated work time, longest single step (≈ per-frame cost with LibAsync), total elapsed time, entry and step counts. The numbers are stored on `BMU.ownHousesCacheStats` / `BMU.houseTourCacheStats` and printed to chat in Debug Mode, so the LibAsync gain (bounded per-frame cost instead of one long blocking frame) can be verified in game.
- House Tours: the initial search is now started as soon as the addon loads (when the House Tours display is enabled) instead of waiting for the first list refresh; the enrichment of the results stays in the background via LibAsync, so the startup time is not penalized.
- House Tours: the enrichment of the search results (zone, names, maps, fixed data...) now runs in the background via LibAsync (task `BMU_HouseToursCache`) instead of blocking the frame at the end of each search; a new search during the enrichment cancels the running task (generation guard), and the fallback is synchronous when LibAsync is absent. A failing listing is skipped without interrupting the rest (house 102 "world map" variant built before insertion), concurrent searches stay blocked during the build, and the game's House Tours filters are always restored.
- Optimized house display: the owned houses database (zone, collectible, names, icon, category, parent map...) is now built once in a cache, in the background at addon startup, instead of being recomputed on every refresh of the main list and the Houses tab. Filters, sorting and per-entry enrichment (addInfo_2) are still applied on every refresh.
- The cache fill is spread over several frames via LibAsync (now an optional external dependency, see `OptionalDependsOn`) so the startup time is not penalized; a standalone LibAsync installed by the user is used.
- Each house's nickname, the primary residence and the furniture count are still read live at display time (renames and changes immediately visible); buying a house or renaming trigger a background cache rebuild, with a 2 s debounce and a never-lost queue if a build is already running (events EVENT_COLLECTIBLE_UPDATED, EVENT_COLLECTIBLES_UNLOCK_STATE_CHANGED and EVENT_COLLECTION_UPDATED, matching the game's collectible manager).
- The traversal order of the cached houses is identical to the direct path, so the house kept per zone ("one entry per zone only" setting and per-zone house preference) does not change.
- As long as the cache is not ready, the old code path is used, so the lists stay correct in all cases; on an error during the build, the existing cache is kept.
- Fixed along the way: in the main list, the formatted name of owned houses (`houseNameFormatted`) was computed with a collectible identifier read before its assignment; the identifier is now assigned before the call, as in the Houses tab.
